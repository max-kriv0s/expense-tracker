# Code Review Guidelines

Правила код-ревью для проекта Expense Tracker. Применяются при ревью PR и при генерации кода с помощью Claude.

---

## Общие правила

- Один PR — одна логическая задача. Если PR затрагивает несколько несвязанных областей — запросить разбивку.
- Изменения, не относящиеся к задаче (форматирование, рефакторинг, переименования), выносить в отдельный PR.
- Мёртвый код, закомментированные блоки и TODO без трекера — удалять или заводить issue.
- Не вводить новые зависимости без обоснования (размер, maintenance, лицензия).

---

## Архитектура

### Backend (NestJS + CQRS)

- Новый модуль — по образцу `src/modules/categories/`: controller, module, CQRS-команды и запросы, DTO.
- Бизнес-логика живёт только в `CommandHandler` / `QueryHandler`, не в контроллерах.
- Контроллер: принимает HTTP, делегирует в `CommandBus` / `QueryBus`, возвращает ответ.
- DTO валидируются через `class-validator` / zod на входе; ответы типизируются явно.
- Prisma-запросы — только внутри handlers, не в контроллерах.
- Общие типы (используемые и на фронтенде) — в `src/types/index.ts`.

### Frontend (Next.js + FSD)

- Импорты строго вниз по слоям: `widgets` → `features` → `entities` → `shared`.
- Кросс-импорты между фичами запрещены.
- `app/` — только маршрутизация и layout'ы; бизнес-логика — в `features/`.
- Новые shadcn-компоненты — в `src/shared/ui/`.
- Составные layout-блоки (sidebar, header) — в `src/widgets/`.
- Типы сущностей копируются из `backend/src/types/index.ts` в `entities/<name>/model/types.ts`.

## Код

### Именование

- Переменные и функции — camelCase; компоненты React — PascalCase; константы — UPPER_SNAKE_CASE.
- Имена булевых переменных: `is*`, `has*`, `can*`.
- Обработчики событий: `handle*` (не `on*` для локальных функций).
- Файлы: kebab-case для модулей/утилит, PascalCase для компонентов.

### TypeScript

- `any` запрещён. Использовать `unknown` с narrowing или явный тип.
- Не кастовать `as T` без проверки — только там, где тип гарантирован контекстом.
- Экспортировать типы явно (`export type`), не смешивать с runtime-экспортами.
- Не дублировать типы между backend и frontend — использовать `src/types/index.ts` как источник.

### Функции и компоненты

- Функция делает одно. Если функцию сложно назвать — это сигнал к разбивке.
- Не более ~80 строк на функцию; не более ~200 строк на файл — ориентиры, не жёсткий лимит.
- Нет вложенных тернарных операторов и условий глубже 3 уровней.
- Нет магических чисел и строк — выносить в именованные константы.

### React / Frontend

- Хуки и запросы — в `model/` слайса, не прямо в JSX.
- Схемы форм — в `features/<name>/model/schemas.ts` (zod + react-hook-form).
- Нет прямых fetch-вызовов в компонентах — только через `api/` слой.
- `key` в списках — стабильный идентификатор, не индекс массива.
- Нет `useEffect` для синхронной производной логики — использовать `useMemo`.

## Безопасность

- Пользовательский ввод не передаётся напрямую в SQL / shell / eval.
- JWT-секрет и DATABASE_URL — только через переменные окружения, не в коде.
- Токены не логируются и не сериализуются в ошибках.
- На backend все защищённые эндпоинты покрыты `JwtAuthGuard`.
- CORS разрешён только для нужных origin'ов (не `*` в production).

---

## Комментарии и документация

- Комментарии — только для неочевидного: скрытое ограничение, обходное решение, нетривиальный инвариант.
- Не комментировать то, что понятно из имён идентификаторов.
- JSDoc / docstring — только для публичных API-функций shared-слоя.

---

## Что блокирует мёрж

- `any` без обоснования
- Нарушение FSD-слоёв (импорт вверх по иерархии или кросс-фича)
- Бизнес-логика в контроллере или в `app/` Next.js
- Секреты или credentials в коде
- Незащищённый эндпоинт
- Дублирование типов вместо использования `src/types/index.ts`

## Что не блокирует, но требует комментария

- Компонент > 200 строк без явной причины
- Отсутствие обработки ошибок на UI (пустые состояния, loading)
- Магические числа без константы
- Неиспользуемые импорты / переменные

## Пропускать

- Сгенерированные файлы миграций в prisma/migrations/\*
- Изменения в \*.lock файлах
