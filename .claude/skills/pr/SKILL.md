# Create Pull Request

## Аргументы

- $0 - название PR
- $1 - базовая ветка (куда мерджим), по умолчанию `main`

## Алгоритм

1. **Определи ветки**:
   - HEAD-ветка (источник): `git branch --show-current`
   - Базовая ветка (цель): `$1`, если не передана — `main`
   - Если HEAD-ветка совпадает с базовой — остановись: PR в себя невозможен.
   - Если HEAD-ветка `main` — остановись: PR из `main` запрещён.

2. **Убедись, что HEAD-ветка актуальна относительно базовой** (параллельно):
   - `git log $1..HEAD --oneline` — коммиты HEAD-ветки
   - `git log HEAD..$1 --oneline` — коммиты `$1`, которых нет в HEAD

   Если HEAD отстаёт от `$1` — предупреди пользователя и предложи `git rebase $1`. Дождись решения пользователя.

3. **Собери информацию для тела PR** (параллельно):
   - `git log $1..HEAD --oneline` — все коммиты HEAD-ветки
   - `git diff $1...HEAD --stat` — изменённые файлы

4. **Составь тело PR** на основе собранной информации, строго по шаблону:

   ```
   ## Summary
   - <bullet-point список: что реализовано / изменено>

   ## Details
   <Подробности по нетривиальным решениям. Если нет — опусти секцию.>

   ## Test plan
   - [ ] <что нужно проверить вручную>
   ```

   Язык тела — **русский**. Заголовок PR — **английский**.

5. **Покажи пользователю итоговый план**:
   - ветка-источник → `main`
   - заголовок PR
   - тело PR

   Дождись явного подтверждения.

6. **Запушь ветку** (если ещё не запушена или отстаёт от remote):

   ```bash
   git push -u origin <current-branch>
   ```

7. **Создай PR** через `gh`:

   ```bash
   gh pr create --title "$0" --base $1 --body "$(cat <<'EOF'
   <body>
   EOF
   )"
   ```

8. **Выведи ссылку на созданный PR**.

## Справочник — Conventional Commits (заголовок PR)

Формат: `<type>(<scope>): <description>`

### Типы

- `feat` — новая функциональность
- `fix` — исправление бага
- `refactor` — рефакторинг без изменения поведения
- `style` — форматирование, отступы
- `test` — тесты
- `docs` — документация
- `chore` — инфраструктура, зависимости, конфиги

### Области

- `auth`, `expenses`, `categories`, `transactions` — фичи
- `backend`, `frontend` — приложения в целом
- `db`, `api`, `ui` — технические слои

### Правила описания

- Английский язык, повелительное наклонение («add», «fix», «remove»)
- Без заглавной буквы в начале и точки в конце

---

## Ограничения

- Не создавать PR без явного подтверждения пользователя
- Не создавать PR из ветки `main`
- Один PR — одна логическая задача
- Описание пишется на русском языке; title — на английском
- После успешного создания PR напомнить пользователю удалить ветку после мержа: `git branch -d <branch>`
