# Детальное описание API

Базовый URL: `http://localhost:3001/api`
Интерактивная документация (Swagger UI): `http://localhost:3001/api/docs`

Все защищённые маршруты требуют заголовка:
```
Authorization: Bearer <access_token>
```

---

## Аутентификация и пользователи

### POST `/api/users/register`

Регистрация нового пользователя.

**Тело запроса:**
```json
{
  "email": "user@example.com",
  "name": "Иван",
  "password": "secret123"
}
```

| Поле | Тип | Правило |
|------|-----|---------|
| `email` | string | валидный email |
| `name` | string | непустая строка |
| `password` | string | минимум 6 символов |

**Ответ `201`:**
```json
{
  "access_token": "eyJ...",
  "refresh_token": "eyJ..."
}
```

**Ошибки:**
- `409` — email уже занят

---

### POST `/api/users/login`

Вход в систему. Также используется для обновления токенов — при передаче `refresh_token` вместо пароля.

**Тело запроса (обычный вход):**
```json
{
  "email": "user@example.com",
  "password": "secret123"
}
```

**Тело запроса (обновление токена):**
```json
{
  "email": "user@example.com",
  "refresh_token": "eyJ..."
}
```

**Ответ `200`:**
```json
{
  "access_token": "eyJ...",
  "refresh_token": "eyJ..."
}
```

**Детали:**
- `access_token` — живёт **60 минут**.
- `refresh_token` — живёт **7 дней**.
- Пароль хэшируется через argon2. Сравнение — `argon2.verify()`.

**Ошибки:**
- `401` — неверный email или пароль / невалидный refresh_token

---

### GET `/api/users/me` 🔒

Получить данные текущего пользователя.

**Ответ `200`:**
```json
{
  "id": "uuid",
  "email": "user@example.com",
  "name": "Иван",
  "createdAt": "2025-05-31T10:00:00.000Z"
}
```

**Ошибки:**
- `401` — токен отсутствует или истёк

## Категории

### GET `/api/categories` 🔒

Получить все категории текущего пользователя.

**Ответ `200`:**
```json
[
  {
    "id": "uuid",
    "name": "Продукты",
    "icon": "🛒",
    "color": "#4CAF50",
    "userId": "uuid"
  }
]
```

---

### POST `/api/categories` 🔒

Создать новую категорию.

**Тело запроса:**
```json
{
  "name": "Транспорт",
  "icon": "🚌",
  "color": "#2196F3"
}
```

| Поле | Тип | Обязательность |
|------|-----|---------------|
| `name` | string | обязательно |
| `icon` | string | опционально |
| `color` | string | опционально |

**Ответ `201`:** объект созданной категории (см. схему выше).

---

### PATCH `/api/categories/:id` 🔒

Обновить категорию. Все поля опциональны — можно передавать только изменяемые.

**Параметры пути:** `id` — UUID категории.

**Тело запроса:**
```json
{
  "name": "Новое название",
  "color": "#FF5722"
}
```

**Ответ `200`:** обновлённый объект категории.

**Ошибки:**
- `404` — категория не найдена
- `403` — категория принадлежит другому пользователю

---

### DELETE `/api/categories/:id` 🔒

Удалить категорию.

**Параметры пути:** `id` — UUID категории.

**Ответ `200`:** удалённый объект категории.

**Ошибки:**
- `404` — категория не найдена
- `400` — категория используется в транзакциях (нарушение FK)

## Транзакции

### GET `/api/transactions` 🔒

Получить список транзакций с фильтрацией. Возвращает результаты, отсортированные по дате убывания.

**Query-параметры (все опциональны):**

| Параметр | Тип | Описание |
|----------|-----|----------|
| `dateFrom` | ISO 8601 date string | начало диапазона дат (включительно) |
| `dateTo` | ISO 8601 date string | конец диапазона дат (включительно) |
| `type` | `INCOME` \| `EXPENSE` | фильтр по типу |
| `categoryId` | UUID | фильтр по категории |

**Пример запроса:**
```
GET /api/transactions?type=EXPENSE&dateFrom=2025-05-01&dateTo=2025-05-31
```

**Ответ `200`:**
```json
[
  {
    "id": "uuid",
    "amount": 1500.50,
    "type": "EXPENSE",
    "description": "Продукты",
    "date": "2025-05-15T00:00:00.000Z",
    "categoryId": "uuid",
    "userId": "uuid",
    "createdAt": "2025-05-15T12:00:00.000Z"
  }
]
```

**Детали реализации:**
- Prisma возвращает `amount` как `Decimal` — в ответе приводится к `number` через `parseFloat`.
- Фильтр по дате: `dateFrom` → `gte`, `dateTo` → `lte`.

---

### GET `/api/transactions/summary` 🔒

Получить сводку доходов и расходов за конкретный месяц.

**Query-параметры (оба обязательны):**

| Параметр | Тип | Диапазон |
|----------|-----|---------|
| `month` | integer | 1–12 |
| `year` | integer | 2000–2100 |

**Пример запроса:**
```
GET /api/transactions/summary?month=5&year=2025
```

**Ответ `200`:**
```json
{
  "totalIncome": 50000,
  "totalExpense": 32000,
  "balance": 18000
}
```

**Детали реализации:**
- Период вычисляется в UTC: `[первое число месяца, первое число следующего)`.
- Агрегация через `prisma.transaction.groupBy({ by: ['type'], _sum: { amount: true } })`.

### POST `/api/transactions` 🔒

Создать новую транзакцию.

```json
{
  "amount": 1500.50,
```

| `description` | string | опционально |
| `date` | ISO 8601 date string | обязательно |
| `categoryId` | UUID string | обязательно |

**Ответ `201`:** объект созданной транзакции.

---

## Коды ошибок

| Код | Значение |
|-----|---------|
| `400` | Неверные данные запроса (валидация) |
| `401` | Не авторизован — токен отсутствует, истёк или невалиден |
| `403` | Нет прав на ресурс |
| `404` | Ресурс не найден |
| `409` | Конфликт — ресурс уже существует |

**Формат ошибки:**
```json
{
  "statusCode": 401,
  "message": "Неверный email или пароль",
  "error": "Unauthorized"
}
```
